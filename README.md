# CS 255 – DriverPass System Analysis and Design

**Charles Kwena | Southern New Hampshire University | October 2026**

## Project Overview and Reflection

The DriverPass project focused on designing a system for a company that wanted to help customers prepare for their driving tests. DriverPass needed a web-based system where customers could set up accounts, buy training packages, schedule driving lessons, take online practice tests, and keep track of their progress. The system also needed to work for employees, including the secretary, driving instructors, management, and IT staff. I think I did a good job taking the client's interview and translating it into system requirements and diagrams that explain how different users would interact with the system.

If I could revise one part of my work, I would improve the UML diagrams by making the relationships and alternate workflows clearer, especially what happens when appointments are unavailable or need to be changed. I approached user needs by focusing on what each person needed to accomplish. Customers needed convenient scheduling and training access, while employees needed the right tools and permissions to manage their responsibilities. Designing around these needs matters because software can technically function but still be frustrating or ineffective if it doesn't solve the actual problem.

Going forward, I would begin software projects by reviewing the client's goals and gathering requirements before jumping into implementation. I would identify the main users, map their workflows, and check that the design addresses each requirement. Use case, activity, sequence, and class diagrams are techniques I would continue to use because they make complicated systems easier to understand, review, and discuss with both technical and nontechnical stakeholders.
